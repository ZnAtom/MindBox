# Mind Box：进度与下一步

更新：2026-10-13。产品设计与技术讨论已分开管理，已有字段和架构草案，尚未开发、实测或制作视频。

标记：`[x]` 已完成；`[ ] ★` 已讨论或有草案，尚未定案；`[ ]` 未开始。完成指本阶段产出，不代表效果已验证。

## 进度

- [x] **1. 首轮用户调研。** 已完成 [第一次](survey/1.md) 和 [第二次](survey/2.md) 宿舍走访。少囤货的人需求弱；第二次明确接受固定位置、批量放入，拒绝逐件登记和规划。室友的需求仍是待直接确认的线索，后续补访不阻塞方案讨论。
- [x] **2. 使用底线。** 可以轻微调整收纳习惯，不能强制增加日常录入、扫码、逐件说话或确认。用户主动查询、补充、设定提醒是可选服务。是否在真实使用中做到，待验证。
- [ ] ★ **3. 价值与 AI 作用。** 主张已明确：Agent 替用户记忆物品。AI 负责识别、理解意图和结合库存回答；程序负责记录与调度。与现有办法相比能否减少整体负担，仍待验证。
- [ ] ★ **4. 产品形态。** 已归入 [产品设计目录](product-design/product-concept.md)，区分候选必做、加分项和本次不承诺的能力，等待你审阅补充。
- [ ] ★ **5. 数据与技术方案。** 已记录 K230、3 门磁、2 个 20 kg 称重、711 AD、ESP32 音频及机械配件；[技术讨论](technical/technical-discussion.md)已有字段、设备分工、通信、供电与采购候选，待你决定；确认后进入 [技术方案](technical/technical-solution.md)。
- [ ] **6. 基础效果验证。** 方法与候选目标已写入技术讨论；实测尚未开始。核对硬件，比较 AI 模型的识别效果、检测速度和端到端延迟，测试重复/漏记、错删、重连和提醒稳定性，再确认是否需要多摄像头。
- [ ] **7. 锁定 48 小时范围。** 技术评估后确认必做范围、验收条件、删减顺序与失败退路。
- [ ] **8. 开发与验证计划。** 范围确定后安排开源复用、分工、时间、联调、重复演示与备用方案。
- [ ] ★ **9. 外观与展示。** 已有真实宿舍问题、产品演示、未来短片的叙事方向，以及 3 分钟苹果 Callback 候选；具体脚本、外观和视频尚未制作。

## 下一步

1. **补齐硬件型号与现有程序。** 核对 K230/ESP32 板型、摄像头、711 模块、ESP32 录播例程和可用 API，避免买重复或不兼容的硬件。
2. **你审阅设计与技术草案。** 确认核心体验，修改字段与显示方式，选择要验证的计算/通信方向；目前推荐先评估电脑集中管理。
3. **执行基础效果验证，再锁定范围。** 首先验证无遮挡单件、小批量与库存更新；按第 6 项记录真实结果，再决定模型、多摄像头、语音分工和电池方案，进入第 7 项。

## 保留事项

- 遮挡后逐步补全与入库时间回推：加分项，可不做；需区分首次看见、推测入库、真实观察到的入库。
- 每日水果照片与外观变化：加分项，不保证食品安全判断。
- 3 分钟苹果提醒 Callback：可选展示巧思，若采用须真实登记并执行定时任务。
- 晚上可继续访问实际囤货者及未在场室友，补充真实损失和习惯证据。
