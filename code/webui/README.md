# Mind Box 网页

第一台柜体已接本机后端库存：自动更新物品、位置、证据图与操作进度，支持补录、修改和标记取出；本地样例不会混入真实柜子。设备开合和实时画面继续来自K230桥接与ArUco视觉。第二台柜体、添加的预览设备和提醒仍使用本地预览；提醒尚不定时送达。

## 运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
```

打开终端显示的地址，默认是 http://127.0.0.1:5173/。端口占用时 Vite 自动选择下一个端口。

### 自动记录与库存

另在`code/backend`启动`python -m app.server`，默认端口8787；模型配置与完整启动顺序见[后端说明](../backend/README.md#自动记录服务)。Vite把`/api/inventory`、`/api/recording`代理至后端，其他设备接口仍代理至8765。可在启动Vite前通过`MIND_BOX_BACKEND_URL`指定其他后端地址。

第一台柜子的手动演示取放和开关按钮禁用。场景右上角的眼睛扫描图标切换“物品识别”，默认关闭；开启后从下一次完整开合开始采集并识别，已打开的抽屉需先关闭。开启期间每次合柜后后台识别，网页约1.2秒刷新库存；模型工作较慢时显示识别队列。记录按钮可看操作列表、逐帧核对、重试或核对后忽略；重试需要先开启识别，物品页始终可人工补录。提交有版本检查，冲突时不会覆盖新记录。服务失联保留当前页最后一次真实快照并显示未连接，不回退为样例库存；刷新页面需重新读取后端，未观察的初始库存不视为已确认空柜。

演示时可点击主界面右下角的小回转箭头“重置取放演示”：第一台柜体下一次完整打开再关闭时播放取出动画，之后每次完整开合播放放入动画；再次点击重新从取出开始。只显示通用物品动画，不修改SQLite库存，不使用图像识别结果判断方向。当前已打开的抽屉不计入重置后的下一轮；重复状态、未知状态和连接中断不会被当作完整开合。动画始终可用，刷新页面后顺序也会从取出开始。

物品识别关闭时仍检测抽屉码、显示开合和取放动画，但不新增后台视频识别会话，也不理解本轮收纳语音。识别开关由后端统一管理，刷新页面或其他标签页会同步状态；重启后端默认关闭。关闭会中止未完成的采集、暂停排队任务，并阻止正在识别的视频结果写入库存；已发出的远端请求无法撤回。重新开启不会补跑关闭期间的操作或旧队列。电脑端滚动缓存、麦克风录音、手动语音和中文唤醒保持运行。

### K230 按键联动

从项目根目录运行 `python3 -u code/device/k230/pc_door_bridge.py`，在 VS Code CanMV 运行 `code/device/k230/k230_key_door.py`。IO21 KEY 连续按 1/2/3 次分别切换第一台柜体上/中/下层；松开后约 500 毫秒判定一组。摄像头持续输出 1280x720 图像，电脑持续接收并缓存最近十秒；第一台柜体有抽屉打开时，概览面板显示实时画面。启用电脑麦克风录音时，按 [K230 接入说明](../device/k230/README.md) 安装音频依赖，并使用 `.venv/bin/python` 加 `--record-audio` 启动桥接。

`vite.config.js` 将 `/api/doors`、`/api/camera`、`/api/audio` 和 `/api/vision` 代理到 `127.0.0.1:8765`；`/api/voice`、`/api/reminders`和库存/记录代理到统一后端`127.0.0.1:8787`。页面通过SSE接收门状态、MJPEG显示画面；按钮录音和文字交代调用同一助手，第一台柜子的物品搜索与提醒保存到SQLite。提醒到点后显示并尝试浏览器TTS播报，结束后发送回执；自动播放失败可在提醒列表点击播放。第二台柜体继续预览交互。桥接失联保留最后姿态并显示未连接，不把缓存帧当成实时画面。

底部“问问 mind box”打开语音面板，点击麦克风按钮后由浏览器直接采集电脑麦克风，再把 WebM 音频发送给本地 `voice_api`。服务本地转写、调用远程 AI 查询 `code/backend/var/mind-box.sqlite3`，回答返回浏览器并使用本机语音合成播报。录音权限由浏览器请求；密钥只放在后端 `.env`，不进入前端。

### 视觉代替门磁

在桥接增加 `--door-source vision`，并按 [设备文档](../device/k230/README.md#用摄像头代替门磁) 安装视觉依赖。摄像头固定在柜体上方向下拍，1/2/3 标记朝上贴在上/中/下层，关闭时隐藏、打开时可见，每次只打开一层。打开 `/vision.html` 或设置中的“视觉识别”可打印标记，无需几何标定和参考码 0。唯一编号持续约 0.3 秒确认打开，连续 2 秒无抽屉码确认关闭；短暂丢码保持原姿态。板端继续运行同一个持续摄像头脚本，KEY 不参与开合控制。

`vision.html` / `vision.js` / `vision.css` 包含带编号的实时画面、码可见性、抽屉状态、确认倒计时和三张码的A4打印版。视频使用持续MJPEG，识别标注独立更新。多码冲突时显示待确认并保留上次姿态。长时间遮挡仍可能误判关闭，需要正确贴码。自动记录后端沿用同一视觉状态时间轴确定真实层号。

修改桥接端口时设置`MIND_BOX_BRIDGE_URL=http://127.0.0.1:<端口>`再启动Vite和后端。`--simulate`仅用于电脑测试，不自动提交库存。缓存接口、运行前提和故障处理见[K230接入说明](../device/k230/README.md)。电脑麦克风仍独立录WAV；音画同步、在线语音转写未接入，自动视觉记录无需用户说话。

```sh
npm run build
npm run preview
```

这是模块化前端，需要通过开发服务器或构建后的静态服务打开。此前的单文件页面保存在 `prototype-v1.html`。

新增 `models.html` 可查看实际调用影眸生成的柜体模型，主界面顶部的立方体图标也可进入。此页面支持旋转、缩放、网格检查、双主题、下载和参考图对照；拆分试验可逐件隔离查看。外形模型 9,532 面、约 342 KB；拆分模型合计 10,000 面、8 个网格。拆分结构尚不合格，因此未替换原有抽屉动画。调用工作流与实际结论见 `../modeling/README.md`、`../modeling/RESULTS.md`。

## 可以体验

- 右侧选择设备、添加预览设备、收起或展开面板。
- 浅色、深色、跟随系统三种外观选择；开关物品建议、减少动态效果。
- 物品搜索、按层筛选、修改名称/位置/日期/备注、标记取出。
- 第一台的物品照片来自实际提交证据；详情可展开原始记录画面。没有证据图的手工记录显示通用外形。历史样例素材仅供预览设备使用。
- 添加、编辑、删除、完成预览提醒；支持一次和每日选项。
- 底部文字交互可查询预览物品，例如“充电线在哪”；涉及提醒时打开表单核对，缺少时间不会伪报创建成功。底部语音查询尚未接入；开门期间的电脑录音由桥接服务独立执行，不要求网页保持打开。
- 主场景下方选择抽屉，预览设备的播放图标可演示开合；第一台完全跟随实际设备状态。
- 预览设备的包裹加号、减号演示取放轨迹，第一台禁用；第一台手动标记取出通过后端库存事务更新。
- 概览的实时区域和设置中也有放入、取出演示入口。从物品详情标记取出时同样播放动画。
- 抽屉打开后概览显示摄像头，缺视频源时等待；库存由合柜后的异步识别更新。随口补充信息和语音找物尚未接入该在线流程。

主动收起面板后，普通开合不强制展开。手机默认收起，点右上角图标查看面板。查询是用户主动操作，会展开并显示物品所在层，但不把已关闭的抽屉画成打开。

预览设备、提醒和偏好保存在浏览器`mind-box-preview-v2`；第一台的库存始终以数据库为准。门状态以桥接为准，无连接时显示待确认。当前没有真实提醒送达。

## 文件与后续接入

| 文件 | 内容 |
| --- | --- |
| `index.html` / `style.css` | 页面结构、无玻璃效果的双主题与响应式布局 |
| `app.js` | 真实库存/操作接口、面板/表单、独立预览设备 |
| `cabinet.js` | Three.js 简化柜体、三个独立抽屉、按需渲染 |
| `item-visuals.js` / `public/items/` | 样例照片、来源说明与通用外形映射 |

模型按商家照片的框架、三层和脚轮近似制作，未经过尺寸校准，也不是影眸生成结果。柜体约 1 万三角面，示例物品增加少量几何体；食品包装、瓶装物品和线材使用不同的简化外形，并非物品扫描模型。每层最多显示六个示意物品，实际预览件数仍以列表为准。

采用不透明材质与约 1.35 秒的平滑取放轨迹，无粒子、模糊或玻璃效果。停止操作与动画结束后不持续渲染，页面隐藏时暂停动画。减少动态效果的设置和系统偏好均会跳过运动、保留文字回执。动画中暂时禁用重复演示，设备切换会清除旧动画；数据变化来自预览操作，不依赖动画结束，不会因为取消动效丢失或重复记录。3D 单独加载，失败时保留其他面板与文字反馈。

当前接入本地 K230 门状态和摄像头预览，尚未绑定正式后端设备身份。后续接会话视频、语音转写和库存回执。模型开合、物品候选、正式入库分别更新。正式后端契约以 `../doc/data-contract.md` 为准。

## 照片与模型的统一方式

3D 外形表达物品位置和取放动作，照片帮助辨认具体物品。照片放在固定尺寸的中性底色上，完整显示主体，保留原色；不使用玻璃、模糊、彩色边框或照片纹理贴满模型。图标、照片沿用相同的间距与版式，图片加载失败自动显示类别图标。没有合适类别时使用包裹图标与通用盒状模型，不要求用户先选图标或生成模型。

原型物品可带两个独立的可选字段：

```json
{
  "shape": "can",
  "photo": {
    "thumbnailUrl": "/items/cola.webp",
    "originalUrl": "/items/capture-v10.webp",
    "sourceLabel": "测试视频截图 · 样例",
    "mode": "cutout"
  }
}
```

`shape` 支持 `packet`、`box`、`bottle`、`can`、`cable`、`flat`，缺省根据类别选择，未知类别回退到盒状。`photo` 缺省显示图标；`mode: cutout` 只用于已经去除背景的照片，普通裁剪图仍采用完整显示和留白。以上仅为预览数据，不变更正式后端契约。

三件照片取自仓库已有测试视频帧，手动标定轮廓后去背景、调整朝向、缩小为 WebP；原始画面另存为较小的 WebP。此处尚未实现自动选帧、分割或真实识别。具体文件见 `public/items/SOURCES.md`。正式接入时应同时保留原始证据图，分割失败可直接使用普通裁剪图，不影响物品记录。旧的本地预览会一次性补充这三个样例，不覆盖已有修改；样例取出后刷新不会重新出现。
