# 后端实施计划与验收

日期：2026-10-16。状态：计划；当前仅完成目录与文档，下面业务阶段均未实施。

## 1. 开发顺序

优先得到一个可在没有硬件时运行的服务器闭环，再用真实设备和模型替换适配器。这样可以分别判断业务问题、协议问题和识别问题。

| 阶段 | 要交付什么 | 完成条件 |
| --- | --- | --- |
| P0 工程基础 | 项目配置、依赖锁定、环境变量样例、FastAPI、健康接口、数据库初始迁移、日志 | 新环境可按 README 启动，重启后配置和数据库正常 |
| P1 原始接入与持久化 | 鉴权、事件去重、图片上传、操作关联、模拟 ESP/K230 | 同一事件/图片反复重传不重复创建，冲突内容明确报错，重启不丢已确认数据 |
| P2 库存闭环 | 关键帧上下文、模拟识别器、统一库存事务、审计、库存查询与纠正 | 模拟取放能更新库存；无证据不删；旧任务不覆盖新库存 |
| P3 指令与提醒 | 文本查询、结构化指令、一次性提醒、持久化 jobs/deliveries、网页通知 | “三分钟后”按首次 accepted_at 起算；重启不丢提醒，重复请求不建重复任务 |
| P4 真实视觉 | 接一个已选多模态服务、结构化结果校验、超时和有限重试 | 有实际照片的受控样本报告，能区分正确、错误、未知和调用失败 |
| P5 硬件与语音联调 | 真实 K230、门磁/重量、小智语音桥、播放回执、空闲控制 | 真实拍照入库、库存语音查询、停止对话后的到点播报分别验证 |
| P6 演示与交付 | 运行说明、备份恢复、演示脚本、真实视频、故障备用路径 | 重复演示核心流程，提供实测记录与已知限制 |

P0→P1→P2→P3 为主线。P4 的 API 配置与样本整理可在主线期间准备，模型接入不改变库存写入规则。P5 中设备可逐个接入；语音异常时保留已验证的文本查询与网页提醒。

## 2. 第一轮具体工作包

下一步编码建议依次完成以下三个工作包，每包完成后更新实际状态：

1. **能启动、能存数据。** 建立项目、迁移、初始柜体/位置/设备配置，提供 live/ready 和设备事件入口。实现持久化确认、鉴权及重复事件处理。
2. **能跑一次模拟取放。** 模拟设备产生开门、照片、关门、稳定重量和采集完成；模拟识别器只返回固定样例，写入经校验的库存并可查询。模拟模式必须明确配置和标注。
3. **能完成一次真实调度。** 提交“三分钟后提醒我吃苹果”文本指令，持久化到期时刻，重启后仍能触发网页提醒；随后再接真实识别和语音。

第一轮不需要先确定 GPIO、购买硬件或选完全部云服务，也不需要搭完整前端。交互式 API 文档和模拟脚本足以检查服务行为，后续网页使用同一接口。

## 3. 必须覆盖的业务验证

| 场景 | 应有结果 |
| --- | --- |
| 同一 event_id 或同一设备 boot/seq 重传 | 原始记录和后续业务不重复 |
| 相同消息身份、不同内容 | 409，原内容不被覆盖 |
| 两设备伪造彼此的 device_id 或 operation_id | 拒绝跨设备/柜体访问 |
| 相同帧重复、坏图片、超大图片、路径穿越文件名 | 重复复用，其余拒绝；无越界文件写入 |
| complete 先到、图片后到、图片永远缺失 | 等待明确宽限，最终进入分析或缺证据，不永久卡住 |
| 前重量未知、标定版本变更、多门打开、等重量换物 | 不虚构精确差值和单件归属 |
| 开门/关门乱序、缺事件、断网历史补传 | 保留原始事件并标记顺序质量，不盲目覆盖当前库存 |
| AI 超时、返回无效 JSON、引用不存在物品 | 不发生未经校验的库存写入，可追踪失败与重试 |
| 两次识别结果反序返回、用户中途纠正 | 版本冲突受到保护，旧结果不覆盖新状态 |
| 模型只说“没看见” | 不自动删除原物品 |
| 不同保质期来源或 AI 估计日期 | 真实 expires_on 与估计 review_at 分开 |
| 库存事务中途失败 | 库存、审计与通知全部回滚；重试不重复 |
| 提醒已保存但发送前重启 | 按截止和宽限规则恢复任务 |
| 同一“三分钟后”请求网络重试 | 只有一个提醒，due_at 不被推后 |
| 提醒取消与调度同时发生 | 条件更新决定结果，返回实际触发/投递状态 |
| 设备离线、没有播放 ACK、重复或乱序 ACK | 不误记 played，有限重试与终态不倒退 |
| 网页关闭后再打开 | 提醒调度持续，网页能重新读取当前状态 |
| 备份后清空测试运行目录再恢复 | 库存、照片与待到期任务均可恢复，使用隔离测试目录 |

采用有意义的接口、事务和故障恢复测试，不为每个字段读写重复编写镜像测试。时钟与供应商在测试中可替换，提醒单元测试不实际等待三分钟；真实演示另做计时记录。

## 4. 效果与性能记录

先记录拍摄、上传、稳定等待、模型调用、事务提交、页面可见、提醒调度、首段音频和播放完成各段时间。报告样本数、成功率及 P50/P95，不混用服务器耗时和用户端到端体验。

候选验收目标沿用已有评估思路，待基础测试后确认：受控 30 次取放中正确库存变更至少 27 次，重复入库和无依据错删目标 0；关门到无需追问的库存结果 P95 目标不超过 10 秒；提醒服务器调度偏差目标不超过 1 秒。实际播放延迟另报，不由调度精度推导。

软件测试通过不代表真实传感器精度、摄像头覆盖和扬声器效果通过。实物联调仍须测空闲 30 分钟主动播报、断网恢复、重量噪声和持续运行；详见根目录 system-assessment.md。
