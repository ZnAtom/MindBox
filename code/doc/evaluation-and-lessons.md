v4已人工查看原始0ms帧，抽屉中未见这些包装；模型却选533ms、两包已经进入后的照片作before。第一个窗口最初正确观察三项由absent变inside，与错误初始快照冲突；补看拼图后又把0–200ms说成已有鸡胸肉，覆盖了原正确观察，使错误被“对账一致”掩盖。说明不能默认最后一次模型复核更可靠。下一步需分别验证“最早操作前基线”和“最近稳定快照”，两者不能互相替代；复核逆转既有可见性/身份声明必须保留冲突和双方证据，不能只因符合终态就自动消除pending。这是本轮未解决的流程缺口。

这些结果不是独立留出集准确率，未证明相同SKU多件和快速连续操作可靠，也不代表新视频端到端认物流程已经验证。现有物品描述/品牌误读仍在，不因为动作正确自动变成正确商品信息。全部事件`committed=false`，没有数据库写入。

检查点法的已知盲点：同一个短窗口内拿出又放回，两端状态可能相同而漏掉历史；需要运动/交互驱动的加密检查点及箱口跟踪。当前SIFT是局部外观几何提示，未实现完整手/物跟踪。v7结束帧曾将抽屉背景误匹配为已移除鸡胸肉；视觉观察将其身份保留uncertain，没有据此新增。后续需前景mask、模板质量和匹配分布校验，不能把绿色框当真实在柜证明。

## 历史动作迭代教训

| 发现 | 处理与剩余风险 |
| --- | --- |
| 学校每个请求最多20张图片，初次v7预览HTTP400 | 限制预览，4帧拼图并印PTS标签，状态照片与认物样例分开 |
| 模型把v8存入解释成取放、分段漏掉v7中间操作 | 场景计划只指导阶段与快照；短窗口覆盖，由观察状态推导动作标签 |
| 白色包装混淆、样例图可能被当成当前画面 | 状态调用只给当前照片；SIFT提供带候选ID的当前帧提示，但仍有背景误配 |
| 模型说absent同时说箱内不可见 | 程序降级unknown，记录原声明；不要求模型通过改成“可见”来满足格式 |
| 已解决的冲突还在旧复核队列里，可能覆盖正确观察 | 每次复核前重算当前目标，解决后停止；不确定身份的未变化声明仅记观察缺口 |
| 局部特征几何估计返回零内点，批处理中断 | 先检查内点数量再算凸包面积，补退化场景测试并继续回归 |
| 有限工具参数越界/模型字段嵌套错误 | 时间范围校验，小幅端点归一化；被拒绝时程序在合法窗口补取并留痕；schema错误有限修复 |

迭代证据保留在`state-actions-v1`至`v8`，相同请求可复用缓存；缓存命中不是新的独立模型试验。早期沙箱出现两次WinError10013，与模型拥堵区分。完整新回归结果以`state-actions-v8/action-evaluation.json`为准；“观察consistent”仍需通过独立答案核对。

本次动作迭代日志合计：261次HTTP成功、963,744 tokens、86次缓存命中、19次结构/语义校验拒绝、3次请求失败（2次WinError10013、1次超过20图HTTP400）。其中最终目录`state-actions-v8`累计85次HTTP成功、318,645 tokens、16次缓存命中、4次校验拒绝；包括目标试验和继续全量回归，不能当成8条全新独立调用成本。没有实测到429/5xx/超时；输出格式错误也不应说成网络失败。

最终8段工具日志：`get_inventory_snapshot`调用8次，均返回unavailable；`get_frames`尝试49次，其中程序编排31次、原生function calling 17次、越界后程序修复1次。17次原生调用中1次被范围校验拒绝，因此实际成功取帧48次。此前8次`search_catalog`只复用了认物产物，本轮未重新执行。没有数据库读取或写入，工具结果见`backend/var/review/state-action-calls.json`。33项自动测试通过，包括零内点RANSAC退化回归。

## 1. 成功标准

“流程completed”只表示脚本完成。分别检查：识别大类、物品截图是否独立完整、实例是否关联正确、净库存变化、动作顺序、品牌款式与时间。粗类别正确不等于库存处理成功；食品候选条数碰巧等于真实件数也不证明逐件匹配正确。

首轮在全部输出完成后才阅读`ans.md`；第二轮和v8补测属于在开发样本上的改进，不能当独立盲测。没有正式逐帧框/动作边界标注，以下是人工质性核对，不报告mAP、毫秒边界准确率或泛化成功率。

## 3. 统一失败经验

| 失败类型 | 证据与影响 | 处理原则 |
| --- | --- | --- |
| 错框/背景 | 首轮v3把抽屉当容器；v8补测也提出抽屉，但复核过滤 | 单独验证目标/背景，图像几何合法不是语义正确；比较专门定位/分割 |
| 混框与遮挡 | v4–v6多个包装在同一crop | 每个物品局部检测/分割，保存partial与multiple_objects；被挡住区域不能靠模型恢复事实 |
| 正背面重复 | v6三件变四个候选；v3两候选重用粉色袋 | 关联轨迹、包装轮廓/文字/位置；只提示可能同一件，不按同名强并 |
| 虚构文字/品牌 | 糖果旺旺/旺仔读法漂移；背面补品牌 | 独立OCR/必要旋转和多视角复核；品牌没抄录文字就置空，但抄录本身仍可能错 |
| 高自报置信 | 模型说high仍会错框、错品牌 | high/medium/low只是证据强度，不是准确概率；保留理由与来源，不据此自动提交 |
| 稀疏帧丢过程 | 最多10帧不足以复原v7；锚点不等于稳定前后帧 | 动作区间加密、手退出后再取稳定帧，完整视频始终保留 |
| add/remove/move波动 | 同一v8先move再错误remove；v4错报拿出放回 | 结构化空间状态＋前后匹配＋轨迹复核；不让模型仅凭整体印象定动作 |
| 解释与标签冲突 | v3/v5称add，解释却是原本已存在/无法确认；v8补测remove解释也不充分 | 下一步让模型返回可核对的状态证据，由规则合成动作，冲突转pending |
| RAG宽泛检索 | v2一次查询包含所有类别，饮品排第五 | 按crop描述/OCR逐项检索；当前6条只是词表，相关性不是商品身份证明 |
| 冗余调用 | 工具followup已生成内容，程序随后又请求规范JSON | 下一步在合法schema时复用答复，降低成本；不能为省调用跳过事实核对 |
| 时间被误解 | 已选视角时间不是首次出现，更不是放入时刻 | 保留PTS和事件窗；无时钟锚点的绝对时间为null |

## 4. 为什么要组合前后对比与手/物跟踪

| 方法 | 能解决 | 不能单独解决 |
| --- | --- | --- |
| 操作前后稳定画面 | 最终新增/保留/消失；开门内净库存变化 | 拿出又放回、同款交换、被遮挡与真正取走的区别 |
| 手部/运动检测 | 定位交互区间，指导加密选帧，寻找遮挡前后证据 | 手靠近/二维重叠不证明抓住物品，不能直接触发增删 |
| 物品跟踪＋箱口边界 | 与手一起运动、越过边界、短暂出柜再返回 | 完全遮挡、检测丢失、同款多件及正背面外观突变 |
| 三者融合 | 用稳定快照确定净变化，用轨迹解释中间历史，冲突待处理 | 摄像头根本看不见的信息仍无法可靠恢复 |

本版已实现前后状态对账，下一步先修正基线选取及矛盾复核，再引入手部触发和短时物体跟踪。摄像头固定、抽屉位置可对齐、光照稳定通常比加长提示词更有效。前后画面应在抽屉打开到位、手退出后拍；若第一段操作早于稳定快照，需保留更早证据和未知项；关门后若只看到前板，不能把那张当“箱内已空”。

建议状态证据：`inside/outside/held/occluded/unknown`、可见比例、箱口穿越方向、来源帧、匹配候选与冲突。消失但不可见区域多时只记unseen；轨迹越界且后快照充分可见并缺失才支持remove。出现新物品且有进入/放置证据支持add；只在视频开始时看见属于初始存在。拿出再放回可有历史事件但不新增第二个实体。

v7检验两层目标：快照匹配应得到“软糖新增、鸡胸肉移除、辣条保留”；视频轨迹再还原四步顺序。若只能恢复净变化，明确历史未恢复，不能伪装完整成功。整柜差重只能作一致性辅助，零差重也可能换物。

### 商品熟悉度与物理库存分别设置

| 模式 | 可访问的商品记忆 | 用途 |
| --- | --- | --- |
| cold | 空商品库/空商品索引；允许通用类别定义，首轮关闭网络 | 模拟首次见到新物品；禁止预置目标照片、名称答案或以前的模型结果 |
| warm | 显式指定的较早独立会话verified快照，只读种子；本次新知识写测试副本 | 检验曾存过鸡胸肉后能否减少识别成本、提高名称层级 |
| holdout | 可含其他商品，排除目标product/SKU及其所有视角、近重复样例 | 检验有记忆时遇到陌生物品能否拒绝错误复用 |
| disabled | 完全关闭商品RAG，保持相同输入、模型、其他预算 | 消融对照，区分跟踪改进与记忆带来的收益 |

空知识库不等于空抽屉。物理初始库存独立选择“明确空/给定真实库存/未知”；v7片头已有物品即使在cold模式也应通过当前视频观察，不可将其当新增。warm可包含某商品档案，但不因此预置现实中仍有这一袋。

每次测试创建独立数据库文件和对应assets、检索索引、语义/API缓存及输出目录；检索scope在服务端固定，模型不能改库路径，不允许空测试库静默回退生产库。生产检索服务不能被测试后台任务写入。源商品快照只读，写时使用隔离副本；并发cold与warm测试也应分别保存任务和缓存。

运行清单应包含：视频哈希/会话与产品分组、代码版本、模型别名/配置、提示词哈希、初始库存及可信程度、商品快照ID/内容哈希/种子来源、逻辑as_of截止序号、测试模式、网络开关、编码器版本、调用预算和缓存策略。缓存键至少覆盖当前证据、模式、知识快照/版本、实际召回引用和提示词/提取器配置；warm答复不能命中cold请求。显式复现缓存与全新模型试验分开报告。

ans.md与动作标签只由独立评测器读取，不能进入提示词、检索索引、文件名提示或模型历史。按商品和采集会话划分，而非把同视频邻帧分到训练/测试；v2-v7中的相同包装不能互相作为“未见商品”证据。完全没有SKU的生活物品按可识别的物品类型/实物组划分，并记录划分依据。

在线回放只能看当前已到达帧及当时可用知识，不能用稍后正面提前给早期动作命名；后续补全允许发生，但保存真实更新时间与来源。若测试“本轮学会、下轮复用”，标为顺序学习实验，不能将第二轮称作独立cold。warm与cold比较保持物理基线、视频和预算一致，差异只来自许可的历史知识。

## 8. 视频直传最小测试（2026-10-17）

目标：先验证学校`deepseek-pro`能否直接读取MP4及先后顺序，再决定是否发送历史失败视频。该别名底层模型未知，不能由名称推断为官方DeepSeek某个版本，也不能由图片识别成功推断支持视频。

### 方法与验收

使用`app.video_probe`生成3秒、320×240、8fps、24帧H.264 MP4：每秒一个不同颜色/形状，共三阶段；第二段倒序。颜色和形状随机，期望值只用于程序评测，不放入提示词；文件名不包含答案。视频为无音轨合成素材，本次不测试音频理解。以完整阶段序列及`media_readable=true`为通过条件，顺序错误、只看到首帧、无媒体和非JSON回答均失败。另将同一组画面作为三张图片发送，验证视觉通道是否可用。

每种格式只测两个相反顺序，无并发、不读缓存、不循环调用直到答对；429/408/5xx及传输错误最多3次有界重试。没有学校视频协议文档，因此以下为有限格式探测，**不能证明服务所有上传方式都不支持视频**。

| 输入与实际路径 | HTTP | 语义检查 | 实际观察 |
| --- | --- | --- | --- |
| Chat Completions：`/api/v1/start/chat/completions`，`video_url.url=data:video/mp4;base64,...` | 2次200 | 0/2通过 | 两次均回答无关内容；prompt_tokens均为4，未提供可验证视频证据，疑似网关未正确透传内容，原因未确认 |
| Responses：`/api/v1/response`，`input_video.video_url=data:video/mp4;base64,...` | 2次200 | 0/2通过 | 两次均返回`{"phases":[],"media_readable":false}`，说明未读到可用媒体 |
| Chat Completions：3张`image_url`对照 | 1次200 | 1/1通过 | 正确输出三组颜色、形状和顺序；usage另有582个image tokens |

合计5次HTTP200、2850 tokens；获准联网后未见429/5xx/超时。首次沙箱运行另有3次WinError10013，重试后改用获准宿主网络；这是本机访问限制，与服务拥堵及视频能力失败分开统计。当前样本太小，不能据此推断模型整体视觉准确率。

### 结论与下一步

当前学校别名及已测两种格式**没有跑通视频直传**。HTTP200只表明服务返回回答，不等于识别成功；后续必须保留语义检查，防止无关回答进入动作/库存。图片对照已通过，说明本次失败不能归因为整条接口不可用，但还无法区分是网关格式过滤还是底层模型不支持。

因此未发送v7、v9、v10等失败/冲突录像，未执行新旧动作准确率对比，也没有改善准确率的结论。正式数据库、旧识别结果及原视频均未改动；本模块完全不连接库存库。新增4项有效测试，总计87项通过，报告为`backend/var/review/native-video-tests.xml`。

下一步先取得学校明确的视频上传协议和可用模型ID，或配置明确支持视频输入的其他服务；不凭猜测枚举模型名。如果视频能力通过同样的正序/倒序测试，再固定预算对比v9/v10单次放入、v8开合误判、v7取出后放回，最后再测v4/v6等基线/正背面难例。新旧输入保持同一时间区间及可比画质，视频输出只形成动作建议，仍需校验原始PTS引用、遮挡状态和前后快照；矛盾不得自动写库。

直传接口如果仍不可用，可另外做“一个交互片段的密集时序帧一次输入”实验，保留真实时间标签与操作前后上下文。它可能减少原1.25秒窗口上下文不足，但不是原生视频，本轮尚未用真实录像运行或证明收益。视频服务也可能内部抽帧，届时仍需测试快速取放是否被漏采，不能自动假设上传MP4就解决时序问题。
