### 先看优先级怎么理解

- **P0：先完成可演示闭环。** 允许任意生活物品、每次只操作少量单件；模糊度只提示，可辨物品及动作成立即可用外观名称记录。当前优先解决v7/v8真实观察失败。
- **P1：接设备、语音/日程统一编排。** 因果回放已有逐动作事务，但未完成设备流/业务HTTP；WebUI由用户负责，本轮不改。
- **P2：最后补充复杂场景和识别增强。** 抽屉连续变形、自动分割、联网搜索、复杂遮挡和大规模泛化都不作为黑客松基础闭环的前置条件。

每项都按“因为 → 准备方案 → 简单来说 → 专业来说 → 完成标准”阅读。这里的“专业来说”是模块或算法名称，便于后续查代码和查资料；“完成标准”是实际验收条件，不是口号。

### P0-A：修正“操作前/操作后”的时间判断 [已完成程序改动]

- **因为：** v7 把已经放入软糖后的画面当成了操作前画面，所以漏记软糖；复核时间没有对齐时，还可能把正常变化当成冲突。
- **准备方案：** 程序明确交互开始和结束的时间范围，单独保存物品首次出现时间；复核时按同一帧或相交时间判断，而不是只拿视频末尾的一张图比较。
- **简单来说：** 先搞清楚“物品在动作开始前就在那里”，还是“物品是在这次动作中出现的”，不让动作结束后的照片冒充起始照片。
- **专业来说：** 这是视频事件的端点约束、时间基线建立、`first_seen` 证据和状态机复核规则。
- **完成标准：** v7 能记录软糖；v9 的“手持进入后放稳”仍能记录；v8 拉开或合上抽屉不会凭动作本身产生误取出；v4、v10 原有结果不退化。
- **本次结果：** 已加入计划端点约束、时间方向复核和回归护栏；历史正确观察通过，新模型错误观察仍会 pending，尚未把视觉模型错误伪装成自动成功。

### P0-B：修正“同一个物品被认成两个物品”的问题 [已完成程序改动]

- **因为：** v7 末尾的白色包装被同时认成辣条和鸡胸肉，独立结束快照还把已经取出的鸡胸肉认成仍在抽屉里。
- **准备方案：** 把整帧、候选局部图和跨帧外观提示放在一起比对，先验证实例是否真的是同一件，再决定是否引入分割或连续跟踪。
- **简单来说：** 一张白色包装只能对应一个真实物品；如果照片角度不同，也要确认它是不是同一件，而不是看到相似颜色就新建一个物品。
- **专业来说：** 这是实例级数据关联、跨帧外观匹配和独立快照一致性校验；SIFT 等局部特征只作为提示，不单独决定入库。
- **完成标准：** v7 末帧不再双重计数；v6 正反面不误合并；取出后独立结束快照不会把物品恢复回来；单变量测试通过后再决定是否投入分割/跟踪。
- **本次结果：** 已加入同帧强重叠提示的排他保护和回归测试；不能确认唯一实例时进入 pending，不直接创建第二件库存。

### P0-D：演示协议与质量诊断 [已实现]

- **因为：** 不做逐视频人工标注时，系统必须用可执行的拍摄约束换取可靠证据；否则模糊、遮挡和多件重叠会把视觉错误误传成库存事实。
- **准备方案：** 摄像头固定、视频包住抽屉，一次操作一件，进入视频边缘后放入并松手停留约半秒。Laplacian清晰度/曝光/模型遮挡估计只报警；只有实物不可辨、错框/混框、身份或动作证据不足时pending。
- **简单来说：** 瓶子字糊了但能确认“这一瓶放进去了”，仍记录；不知道内容物就叫“白色袋装物品”，不能猜里面是什么。
- **专业来说：** 这是开放集描述、输入质量门禁和证据驱动的拒识策略，不是固定类别分类器。
- **完成标准：** 饮料、零食、袋装物品、盒装食品等不同物品都能入库；未知物品也能用“白色袋装物品”等描述作为名称；品牌和规格缺失不阻塞入库。
- **本次结果：** 度量/阈值/警告和可辨partial放行已实现，数值未标定为准确率。多样外观命名和灰色低清截图的真实SQLite事务测试通过；没有足够多样新实拍，暂不宣称多样视频验收完成。无需逐视频人工标注抽屉。

### P0-E：v7 四动作因果回放（M5-lite） [代码实现，视频验收未通过]

- **因为：** v7 把四次操作放在同一段上下文中，模型容易混淆前后状态；整段结束后再推理也会重复解释已经发生的动作。
- **准备方案：** 当前用帧差/稳定间隔触发微批，不预先硬切四段；12fps已到达帧与上下文交给模型，跨微批台账累计边缘/放稳证据，再按事件建父media_capture下的子operation；没有使用光流。
- **简单来说：** 把“取出辣条、放入软糖、取出鸡胸肉、放回辣条”分别看，做完一步再把结果交给下一步。
- **专业来说：** 这是因果时序分段、父子操作、状态台账、幂等事务和有界回放；分段不确定时保留整个动作窗口并进入 `pending`。
- **完成标准：** v7 净变化为软糖新增、鸡胸肉移除、辣条保留；同一视频重放不重复写库；合屉动作不会单独产生取出事件。
- **本次结果：** 四动作状态机、return复用item、逐件失败隔离、部分提交恢复及幂等测试通过。真实新入口v9提交1件；v7四动作仍失败、v8放稳证据不足。建议下一步固定相同输入和状态机，优先换已测GPT做因果对照，不能用整段GPT预测代替已写库验收。

### P0-F：开放集命名和最小入库回执 [已实现]

- **因为：** 物品种类不能限定为少数类别，但模型也不一定能识别品牌或 SKU。
- **准备方案：** 输出“类别 + 可见外观 + 包装形态”的可读名称，例如“绿色瓶装饮品”“白色袋装零食”“未知盒装食品”；视觉、OCR、RAG 和用户修正分别记录来源，后续补全不能覆盖原始描述。
- **简单来说：** 不知道商品名时也要给一个有区别的描述，保证多样物品不会全部变成“未知物品”。
- **专业来说：** 这是开放世界识别、属性化命名、实例身份关联和字段级来源追踪。
- **完成标准：** 每个已确认物品都有非空名称、粗类别、外观描述、时间、抽屉位置、证据帧和置信等级；名称相似不等于实例合并。
- **本次结果：** session.results含实物ID、名称/类别/外观、动作、位置、媒体时间窗、证据、支持度、quality及真实提交ID。未知类别允许“未知”，历史视频绝对stored_at保持null；支持度不是识别概率。v9已有真实回执，未知描述多样性通过程序测试。
